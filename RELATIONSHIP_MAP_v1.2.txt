RELATIONSHIP PRESERVATION RULE
1. Never rename, remove or repurpose an existing foreign key without dependency review.
2. Before adding a relationship, check this map and the current schema.
3. Prefer additive migrations: CREATE TABLE / ADD COLUMN / ADD CONSTRAINT.
4. Every new relationship must be documented here and in version history.
5. company_id remains the multi-company ownership boundary.
6. customer_id remains the customer ownership link for part numbers and captures.
7. Authentication changes access determination only; it does not replace company_id.
