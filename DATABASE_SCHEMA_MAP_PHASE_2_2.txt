GUVEL Operational — Database Schema Map Phase 2.2

BASELINE
Phase 2.1 Cloudflare Tenant Gateway / Phase 2.0.6 Multi-Tenant Foundation.

EXISTING AUTHORITATIVE TENANT MODEL
companies
- id uuid PK
- name text
- code text UNIQUE
- subdomain text NULLABLE, case-insensitive unique when present
- created_at
- created_by
- updated_at

company_members
- company_id -> companies.id
- user_id -> auth.users.id
- role -> owner/admin/manager/supervisor/viewer
- is_active

PHASE 2.2 ADDITIONS
No new table.
No new foreign key.

Added database functions:
- is_reserved_company_subdomain(target_subdomain)
- is_company_subdomain_available(target_subdomain, exclude_company_id)
- create_company_for_current_user(target_name, target_code, target_subdomain)
- update_company_identity(target_company_id, target_name, target_code, target_subdomain)
- resolve_company_subdomain(target_subdomain) hardened against reserved names

Added trigger:
- trg_validate_company_subdomain on companies

Purpose:
- Enforce valid tenant hostnames at database level.
- Prevent reserved platform hostnames from becoming customer tenants.
- Provide atomic company provisioning for a newly authenticated account.
- Keep owner assignment tied to the authenticated creator.
- Validate company identity updates through a controlled owner-only RPC.

No existing relationship is repurposed or removed.
