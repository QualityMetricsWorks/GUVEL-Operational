PRESERVED RELATIONSHIP:
    shifts.company_id -> companies.id

No existing relationship was renamed or removed in Phase 1.1.
The frontend always filters, updates, and deletes shifts using:
    ACTIVE_COMPANY_ID
and preserves the company_id assigned to each shift.

SHIFT BUSINESS RULES
--------------------
- code must be unique within a company.
- start_time and end_time are stored as time values.
- excluded_planned_minutes is the total Option A value.
- excluded_planned_minutes must be >= 0.
- future OEE calculations must derive planned production time from
  shift duration minus excluded planned time according to the final
  cross-midnight calculation rule.

DATABASE EVOLUTION RULE
-----------------------
1. Review this map before adding or changing any relationship.
2. Reuse an existing relationship when it correctly represents the
   business dependency.
3. If no correct relationship exists, create a new additive structure.
4. Do not drop or rename foreign keys, tables, or columns used by
   existing modules without a dependency review and migration plan.
5. Update this file and the CHANGE HISTORY with every approved change.
6. Prefer additive migrations (CREATE / ADD COLUMN) over destructive
   changes whenever possible.
